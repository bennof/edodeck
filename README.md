# edodeck

An embeddable presentation library. Write your slides as plain HTML sections, include one script and one stylesheet, and call `EdoDeck.init()` — you get a scroll-snap slide deck with step-by-step reveals, transitions, speaker notes, a drawing layer, optional sound, and a print view. No framework, no build step for the page that uses it.

- **Slides are markup.** A slide is a `<section class="slide">`; everything else — menu, progress bar, dots, timer ring, drawing toolbar, notes panel — is generated by `init()`, so it never clutters your content.
- **Fixed design canvas, scaled to fit.** Slides are laid out at 1280×720 (or 1920×1080, 4K, 4:3) and the whole stage is scaled to the screen.
- **Fullscreen or inline.** Take over the page, or embed the deck as one section of a larger page.
- **Reveal, transitions, timers** — fragments with many effects and an explicit order, per-slide transitions, auto-advance with a timer ring.
- **Speaker notes, freehand drawing** (touch-friendly, saved per slide), and a print view with one slide per page.
- **Sound (opt-in):** background music per slide with crossfades, effects per fragment.
- **Dynamic elements** through a small mount/unmount registry, math through the page's KaTeX, YouTube embeds.
- **Themeable** with CSS custom properties, light/dark included. English and German texts.

Demos: [`examples/demo.html`](examples/demo.html) (English) and [`examples/demo_de.html`](examples/demo_de.html) (Deutsch). They load the files in `dist/`, so run `npm run build` first (or `npm run dev`, see [Development](#development)). A copy of KaTeX for the demos is in [`examples/vendor/katex`](examples/vendor/katex).

## Quick start

```html
<link rel="stylesheet" href="edodeck.css">

<div id="viewport">
  <div id="stage" class="res-1080p">
    <div id="deck">

      <section class="slide">
        <h1>Hello</h1>
        <p>The first slide.</p>
      </section>

      <section class="slide" data-notes="Say something clever here.">
        <h1>Second slide</h1>
        <ul data-reveal="sequence">
          <li>One</li>
          <li>Two</li>
          <li>Three</li>
        </ul>
      </section>

    </div>
  </div>
</div>

<script src="edodeck.global.js"></script>
<script>
  EdoDeck.init();
</script>
```

That is the whole required markup: `#viewport › #stage › #deck › .slide`. Unlike the other edo libraries, edodeck does not initialize itself — `init()` takes options and returns a controller.

Navigate with the arrow keys or <kbd>Space</kbd>, by swiping or scrolling, with the dots on the right, or with the menu button in the corner. <kbd>N</kbd> shows the speaker notes.

## Fullscreen and inline mode

By default `#viewport` fills the browser window and the deck owns the page (it also sets `html`/`body` to `overflow: hidden`). To embed a deck as one section of a normal page, give the viewport the class `inline`:

```html
<section id="explanation">
  <div id="viewport" class="inline">…</div>
</section>
<script>
  EdoDeck.init({ root: document.getElementById('explanation') });
</script>
```

An inline deck is a normal in-flow element, as wide as its container, with the height derived from the stage's aspect ratio (like a video embed). The host page keeps its own scrolling and colors, and the deck only reacts to the keyboard while the pointer is over it, focus is inside it, or it is fullscreen — so it doesn't take over the page's arrow keys or Space. The menu's fullscreen button shows just the deck in real fullscreen.

`root` limits where `init()` looks for the deck; it defaults to `document`.

## Generated UI

`init()` creates whatever of this is not already in your markup, inside `#viewport`:

| Element | What it is |
| --- | --- |
| `#annotate-canvas`, `#annotate-toolbar` | The drawing layer and its toolbar (four colors, eraser, clear) |
| `#fab-menu` | The corner menu: previous, next, fullscreen, notes, drawing, print |
| `#progress`, `#dots` | Progress bar and slide dots (click a dot to jump) |
| `#timer-ring` | Countdown ring for slides with `data-duration` |
| `#notes-debug` | The speaker-notes panel |

If your markup already contains one of these elements, it is used as it is. On `destroy()`, only the elements `init()` generated are removed.

The button labels are English or German — see [Language](#language).

## Slides

Attributes and classes on `.slide`:

| | |
| --- | --- |
| `data-notes="…"` | Speaker notes, shown in the panel (<kbd>N</kbd> or the menu). |
| `data-duration="4000"` | Auto-advance to the next slide after this many milliseconds, with a countdown ring. |
| `data-transition="fade\|zoom\|rise\|none"` | How the slide settles in. Default: a gentle rise with a slight zoom. Respects `prefers-reduced-motion`. |
| `data-bg="accent\|warn"` | A tinted gradient background. |
| `bg-cover` / `bg-contain` / `bg-stretch` | Size of a background image given as `style="--bg-src:url('image.jpg')"`. |
| `bg-dim` | A dark overlay on the background image, with light text on top (strength: `style="--bg-overlay:0.6"`, default `0.45`). |
| `data-music="name"` | Crossfade to this music track when the slide becomes active (needs [sound](#sound)). |

A relative `--bg-src` URL is resolved against your page (the browsers that support `@property`; in others, use an absolute URL).

The stage's size comes from its class: `res-1080p` (1920×1080), `res-4k` (3840×2160), `res-4-3` (1024×768), or none for the default 1280×720. Everything inside a slide is measured in pixels of that canvas.

### Step-by-step reveal

Mark a container with `data-reveal="sequence"`: its direct children are revealed one at a time. *Next* reveals the next child; only when all are visible does it go on to the next slide (and *Previous* hides them again first). Free scrolling and swiping skip this.

- `data-order="n"` on a child sets its position in the sequence, independent of the markup order. Children without it use their DOM position.
- A class on the child picks the effect: `fade-up`, `fade-down`, `fade-left`, `fade-right`, `grow`, `shrink`, `fade-out` (starts visible, then disappears), `strike`, `highlight-accent`, `highlight-success`, `highlight-error`, `fade-in-then-out`, `fade-in-then-semi-out` (older items dim, only the current one stays fully visible).
- `data-sound="name"` plays a sound effect when the child is revealed (needs [sound](#sound)).

### Math

`[data-tex]` elements are rendered once as display math:

```html
<div data-tex="x = \frac{-b \pm \sqrt{b^2-4ac}}{2a}"></div>
```

KaTeX is **not** part of edodeck: the page provides it — `katex.min.css` and `katex.min.js` (which defines `window.katex`) loaded before `init()`. Without it, the elements stay empty. To use another engine, pass a renderer: `EdoDeck.init({ renderMath: (el, tex) => … })`.

### Dynamic elements

Register a mount for elements that need code while their slide is shown — a canvas animation, a 3D view, a simulation:

```html
<div data-mount="orbit" data-script-id="demo1"></div>
```

```js
EdoDeck.registerMount('demo1', {
  mount(el)   { /* the slide became active: start */ },
  unmount(el) { /* the slide was left: clean up */ },
});
```

Several `data-mount` elements per slide are supported. Register before `init()`.

### Video

`<div class="yt-embed" data-yt="VIDEO_ID" data-yt-mode="click">` shows the YouTube preview image and loads the video (in real fullscreen) only when tapped; `data-yt-mode="auto"` starts it — muted, as browsers require — when the slide becomes active and stops it when the slide is left. In print, each embed becomes a QR code linking to the video (`https://youtu.be/…`). Videos need a network connection.

## JavaScript API

```js
const deck = EdoDeck.init({
  root,        // where to look for the deck; default: document
  sound,       // { assets: [{ name, url }] } — enables audio, see below
  renderMath,  // (el, tex) => void — replaces the KaTeX rendering
});

deck.advance();                 // next fragment, or next slide
deck.retreat();                 // previous
deck.goTo(6);                   // jump to slide 6 (0-based)
deck.goTo(6, 2);                // …and reveal fragments up to index 2
deck.getCurrent();              // current slide index
deck.getCurrentFragmentIndex(); // -1 = none revealed yet
deck.audio;                     // the AudioManager, or null without sound
deck.destroy();                 // remove listeners and the generated UI
```

`EdoDeck.registerMount(id, { mount, unmount })` is described above. The ESM build (`edodeck.esm.js`) exports the same names, plus the `AudioManager`, `MusicManager`, `SoundManager` and `AudioLoader` classes and the types `InitOptions`, `EdoDeck`, `Deck`, `MountDefinition`, `SoundOptions`, `MathRenderer`.

### Keyboard

| Key | Action |
| --- | --- |
| <kbd>↓</kbd> <kbd>→</kbd> <kbd>Space</kbd> | Next fragment / slide |
| <kbd>↑</kbd> <kbd>←</kbd> | Previous |
| <kbd>N</kbd> | Speaker notes |
| <kbd>Esc</kbd> | Close the menu |

Combinations with <kbd>Ctrl</kbd>/<kbd>⌘</kbd>/<kbd>Alt</kbd> and typing in form fields are left alone. See [Fullscreen and inline mode](#fullscreen-and-inline-mode) for when an inline deck listens.

## Sound

Sound is opt-in: without `sound`, no `AudioContext` is created.

```js
EdoDeck.init({
  sound: { assets: [
    { name: 'theme',  url: 'audio/theme.mp3' },
    { name: 'ding',   url: 'audio/ding.wav' },
  ] },
});
```

```html
<section class="slide" data-music="theme">…</section>   <!-- crossfades to "theme" -->
<li data-sound="ding">…</li>                              <!-- plays when revealed -->
```

Assets are loaded once at start; `data-music` on the very first slide waits for that, while calls you make yourself through `deck.audio` before loading has finished are dropped with a console warning. A slide without `data-music` leaves the current track playing. Browsers keep audio suspended until the first click, tap or key press; the deck unlocks it then. `data-sound` plays on a reveal through *Next*, not on a deep-link `goTo`.

## Drawing and notes

The menu's pen button switches drawing on: freehand lines over the current slide with mouse, touch or pen, with four colors, an eraser and *clear all*. Drawings are saved per slide index in `localStorage` (key `slidedeck_annotations_v1`), so they survive a reload — and two decks on the same site share that key.

## Print

*Print* in the menu (or the browser's print) prints every slide on its own landscape page, with all fragments visible, in a fixed light palette, and with the drawings on their slides. Enable "background graphics" in the print dialog to get background images and colors.

## Theming

Colors are `--edodeck-*` custom properties, with light and dark values (`-light` / `-dark` suffixed), switched automatically by `prefers-color-scheme`. With no preference signaled, the **dark** palette is the default. A page can force a mode by putting a `.light` or `.dark` class on `<html>` (or any ancestor):

```js
document.documentElement.classList.add('dark');
```

| Token | Used for |
| --- | --- |
| `--edodeck-background`, `--edodeck-foreground`, `--edodeck-muted` | Slide background, text, secondary text |
| `--edodeck-accent`, `--edodeck-border` | Accent color, lines |
| `--edodeck-error`, `--edodeck-success` | Feedback colors (also for the `highlight-*` effects) |
| `--edodeck-backdrop` | The area around the stage (letterboxing); derived from the background |

Override any of them from your own stylesheet — for example `:root:root { --edodeck-accent: #7c3aed; }`, whose doubled `:root` also outranks the library's own `.light`/`.dark` rules. The floating controls (menu, dots, notes panel) are deliberately not themed: they float over arbitrary slide content and always stay a dark glass overlay, like a video player's controls.

## Language

The generated UI's texts — button labels, the empty-notes text, the printed video caption — are English or German, chosen by the closest `lang` attribute above the deck (`<html lang="de">`). German for `de` and `de-…`, English for everything else, including no `lang`. Everything on the slides is your own markup.

## Without JavaScript

The slides are ordinary HTML, so without scripting (or for a crawler) the deck degrades to a readable page: the slides sit one below the other, all visible, and can be scrolled normally. Everything JavaScript provides — the scaled stage, snapping, reveals, the menu, math, video players — is simply absent, and `[data-tex]` formulas and video embeds stay empty (embeds are hidden). This needs the `(scripting: none)` media feature; a browser that doesn't know it keeps the normal layout.

## Browser support

A current evergreen browser. The stylesheet uses `:has()` (scoping its page rules to fullscreen mode; Chrome 105+, Safari 15.4+, Firefox 121+), `color-mix()`, `@media (scripting)` (Chrome 120+, Safari 17+, Firefox 113+) and, for relative background URLs, `@property`. After scrolling, the deck re-aligns to the current slide on `scrollend`, where supported.

## Limitations

- No presenter view (a second window with notes) yet, and untested on iOS Safari fullscreen with video embeds.
- Drawings and everything else are per browser: nothing is synced.
- The tests cover the QR encoder only (`npm test`); the rest of the library is checked by hand in the demo.

## Development

```
npm install
npm run dev        # watch + local server: http://127.0.0.1:8080/examples/demo.html
npm run build      # dist/edodeck.{esm.js,global.js,css} + type declarations
npm run typecheck
npm test           # the QR encoder against a reference implementation
```

Sources are in [`src/`](src/): `index.ts` is `init()`, `core/` holds the deck state, fragments, mounts, notes, auto-advance, print and stage scaling, `features/` the drawing layer, menu, generated chrome, video and sound bridge, `audio/` a standalone audio mini-library, and `styles/` all CSS.

`features/qr.ts` is a small QR Code encoder of its own (byte mode, error correction level M, versions 1–10, so URLs of up to 213 bytes) for the print view. `npm test` checks it against the `qrcode-generator` package (a dev dependency, not shipped) for every text length from 1 to 213 bytes.
